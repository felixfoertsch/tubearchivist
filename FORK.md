# Fork ownership and images

`main` is directly maintained source. Upstream source is not fetched, replayed, or used to regenerate history. Contributions use normal commits and pull requests; releases are published manually, not generated by CI.

## CI and publication

`.github/workflows/image.yml` validates pull requests, `main` pushes, and published releases. Validation retains pre-commit, backend pytest, the frontend rolling-window test, and the frontend production build. Docker builds use Node.js 24.21.0 and export OCI archives for `linux/amd64` and `linux/arm64`.

- `main` pushes publish `ghcr.io/felixfoertsch/tubearchivist:nightly`.
- Published non-prerelease releases publish their exact tag, `stable`, and `latest`.
- Prereleases and pull requests never publish.
- Release image tags cannot overwrite existing tags. Retries accept an existing exact tag only when its manifest digest matches the same OCI artifact, then resume guarded alias promotion. To release changed source, use a new tag and release. Release tags must be valid Docker tags and cannot be `nightly`, `stable`, or `latest`.

Builds check out the exact event SHA with no persisted Git credentials and read-only permissions. A separate GitHub-hosted publisher has package-write permission but never checks out or executes repository source. It consumes only an OCI archive from the same run, validates platform and source/revision labels, and uses only `GITHUB_TOKEN`. Published multi-architecture images are inspected again before aliases move.

Publication is serialized across both channels. Before each alias update, CI checks current `main` or the exact release tag and GitHub's latest non-prerelease release. Stale builds fail closed. GitHub's latest-release selection controls stable ordering; publish releases in intended order and do not manually mark older releases latest. Main candidates use unique `build-<run-id>-<attempt>` tags; they may remain after a stale run. Registry tag writes and GitHub ref updates are separate services: an external ref change during a registry request cannot be atomic; the next validated run restores the current channel. Never move published release tags or change publication aliases outside CI.

No source pushes, automatic releases, upstream registry publication, or deployments occur. Inherited `deploy.sh` targets upstream registries and is not this fork's publisher; do not use it to release fork images.

Run the stdlib workflow contract check with `node scripts/test-workflow.mjs`. Full builds and registry checks run on GitHub-hosted ephemeral runners.

## Channel rolling window

Set optional channel override `channel_overwrites.rolling_window_size` to a
positive integer N from 1 to 2147483647 to use N as the regular-video subscription
page size. The flat query trusts YouTube's newest-first videos tab order; it does
not scan full-channel metadata or make per-video admission requests.
Set it to `null` to disable rolling-window management; disabling does not restore
previously deleted videos. Normal-video page size `0` also disables this rolling
scope. Existing watched-age cleanup still applies when rolling is disabled; this
option does not freeze all deletion. Existing subscription and download schedules
stay in control; enabling this option does not create a new schedule. Ignored
videos and channel title filters remain respected. Shorts and streams stay untouched.

**Warning:** Enabling this option lets the channel delete older regular videos,
including watched, unwatched, manually downloaded, and playlist-downloaded videos
already in your library. Keep separate backups for videos you want to preserve.

After subscription scans and successful download batches, one bounded flat query
fetches the latest N regular-video IDs. Failed or empty queries skip pruning, as
do pending regular downloads. Once downloads finish, archived regular videos
outside that set are deleted and added to the normal ignore queue. Shorts and
streams are never pruned. Unavailable or members-only entries can leave fewer
than N archived videos; no replacement is required for those entries.

Deleted videos stay ignored until explicitly un-ignored, including after disabling
the window with `null`. Manual, playlist and rescan additions respect that ignore
queue. Pending downloads can temporarily leave more than N archived videos.
